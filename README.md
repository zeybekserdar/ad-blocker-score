# Ad Blocker Score

> Ad Blocker & DNS Blocking Test

A static page that measures what your browser's ad blocker (uBlock Origin, AdGuard, Brave) and your DNS filter (Pi-hole, AdGuard Home, NextDNS) actually block. No build step, just plain HTML/CSS/JS. The UI is available in English and Turkish.

**Live:** https://zeybekserdar.github.io/ad-blocker-score/

## What gets tested

The main score is out of 100. Category weights live in `js/tests.js`:

| Category | Points |
| --- | --- |
| Ad networks | 24 |
| Analytics | 19 |
| Cosmetic filtering | 14 |
| Social media trackers | 9 |
| OEM telemetry & error tracking | 9 |
| CNAME-cloaked trackers | 8 |
| Mobile SDKs | 7 |
| Pop-ups | 5 |
| Malware / scams | 5 |

On top of that:

- A Türkiye pack (Admatic, ReklamStore, AdMost, Gemius, Insider, Netmera, Segmentify...). When it's on it counts for 5 points; it's on by default in the Turkish UI.
- Content filters (gambling, piracy, social networks, DoH/VPN, URL shorteners). These get their own percentage and don't affect the main score.
- Any scored category can be left out of the score with the "Count in score" box on its card (say, social trackers you keep for social logins). It is still tested, but its weight drops out and the rest are rescaled to 100. Its domains are also left out of the generated rules.

## How it works

Every domain gets a `no-cors` fetch. First a control group of 8 neutral addresses runs, and the "fast failure" threshold is derived from their median response time. Failed requests are retried once:

- both attempts fail fast: blocked,
- both are slow: the server is up but refuses the request, counted as passed,
- slow first, fast second: the domain is dead and left out of the score,
- no answer within 5 s: blocked (usually a DNS blocker answering 0.0.0.0).

For cosmetic tests the page injects elements that look like ad slots, and there are bait scripts and images under `ads/` and `adimages/`. DNS can't block those, so the results also tell whether blocking happens in an extension or at the DNS level.

When a run finishes:

- it guesses which HaGeZi tier and OISD lists are active,
- it generates rules for whatever got through, in uBO/AdGuard, Pi-hole or hosts format,
- it shows roughly how much script weight was blocked,
- the result is stored in the browser (last 10 runs) so two runs can be compared.

## Running locally

It uses ES modules, so opening it via `file://` won't work. You need a server:

```bash
python3 -m http.server 8080
```

## List data

`data/lists.json` is generated by `scripts/build-lists.mjs`. It downloads the HaGeZi and OISD lists, checks which lists each test domain is on, its CNAME target and whether it still resolves, and measures the size of a few scripts for the savings estimate. DNS queries go through 1.1.1.1, so a Pi-hole on your machine won't skew the output.

```bash
node scripts/build-lists.mjs
node scripts/selftest.mjs
```

`.github/workflows/update-lists.yml` runs this daily and commits if anything changed. If the file is missing the page still works; only the badges and list detection are hidden.

## Adding tests

Add a line to the right group in `js/tests.js`. If you add a new category, also add `cat.<id>` and `cat.<id>.desc` to `js/locales/en.js` and `tr.js`. Main category weights must add up to 100 (the selftest checks this). After adding domains, run `build-lists.mjs` again so their badges show up.

## Privacy

The page doesn't collect or send any data, and the history only lives in the visitor's own browser. Requests your blocker lets through do reach those servers, of course (without cookies).
